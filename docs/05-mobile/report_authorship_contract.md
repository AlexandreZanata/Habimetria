# Report Authorship, Privacy and Presentation

Normative extension of [local PDF](pdf-ondevice.md),
[domain](../03-architecture/domain-model.md) and
[Brazilian applicability](../03-architecture/brazil_report_legal_requirements.md).
Scope: Android/local processing. This delivery runs code tests only, by user
instruction. Emulator/physical-device/PDF visual validation is deferred to
the user after all phases. iOS runtime qualification is excluded.
No claim of automatic judicial acceptance.

## Optional personal identification

Rental capture/finalization does not require name, CPF, email or phone.
Review offers an explicit optional identification section. CPF format/check
digits are validated if provided, never described as government verification.
Users choose whether the supplied CPF appears fully or masked in the PDF;
the complete voluntarily supplied declaration is in the private signed
Manifest/ZIP. Show this export consequence before collecting/sharing it.
Professional author name/title/council remain necessary to identify the
responsible author. Additional CPF/contact fields stay optional.
No identification-document photo, birth date or unnecessary personal data.

Freeze contract reference, inspection date declared by the author, company,
summary/keywords, documents reviewed, inspection limitations, references and
professional applicability declarations in Manifest v4. Old sealed Manifest
v1–v3 bytes and existing READY PDFs are never rewritten.

## Share declarations and signatures

Report-specific signed declarations bind the exact Report ID, PDF SHA-256
and Manifest SHA-256, with explicit intent: AUTHOR, RECEIVED, AGREED or
DISAGREED. Disagreement requires text. They are appended to the Report
package; never mutate the frozen Inspection, PDF or original receipt.
Actor identification is optional for ordinary declarations. A declaration
recorded on this device remains attributed to its installation key; it
does not prove a remote party received or agreed. No automatic receipt
or agreement is generated by opening/sharing/downloading.

An Android/JVM certificate-holder option imports an A1 PKCS#12 file with
explicit signing intent. Password/private key are not persisted or exported.
The detached certificate signature covers the declaration and exact Report
digests. Display certificate subject/fingerprint, chain validity and
device-time expiry separately from external trust. Revocation stays UNKNOWN
offline and trusted time stays ABSENT until an external ACT token exists;
neither is presented as approved. Reject missing, wrong-password,
unsupported/weak keys, mismatched key and altered payloads.
An included/self-signed certificate is not independently trusted.
No claim that the custom detached format is PAdES or accepted by ITI VALIDAR.
Gov.br signing remains an optional user-controlled external service, not a
manufactured government signature or a mandatory network dependency.

External PAdES, Gov.br and ACT timestamp steps are explicit manual handoffs:
prepare hashes/instructions offline, sign or timestamp a copy outside the app
with the authorized holder certificate/account/TSA, preserve the READY PDF
and register the signed copy under a distinct path. External copies stay
EXTERNAL_UNVERIFIED locally and require ITI VALIDAR or the issuing authority
for any validity claim.

Declarations form an append-only signed chain with an installation-signed
index. Its atomic update commits staged declaration digests; recovery finishes
only exact pending bytes bound by that signed index. Package verification checks exact files/count/order, signatures,
Report binding and declared certificate material. Removed/substituted
declarations fail the signed index. A previously exported package remains
a valid historical snapshot; offline software cannot know later additions.
Keep public verification material; never export a private key/P12/password.

## Professional applicability

Professional review requires explicit acknowledgments of responsibility,
appropriate attribution, applicable registered ART/RRT and selected methods
and references. These are professional declarations, not live council checks.
Any user-recorded consultation source/date stays explicitly declared.
No structural-safety diagnosis is inferred from photographs or app presets.
Full ABNT clause conformity requires licensed standards and scope review;
unreviewed scope is never advertised as compliant.

## Editorial presentation

Use A4, 30 mm left/top and 20 mm right/bottom, body 12 pt, smaller source/
caption/footer text, consistent single-spacing and numbered textual sections.
Professional presentation adds title/identification, author-written summary/
keywords, contents, scope/method, evidence, analysis/conclusions, references
and separately identified technical/integrity appendices. Cover uses a
restrained corporate identity; evidence is not cropped, recolored or altered.

These choices follow public editorial guidance from the
[UFSC tutorial on NBR 10719](https://repositorio.ufsc.br/handle/123456789/198047).
This is an implementation baseline, not a certified reproduction of every
clause or a replacement for NBR 13752/16747 technical requirements.
Preserve physical-page traceability and disclose numbering conventions.

## Preservation and qualification

Disable Android automatic backup of private evidence/signing material.
Bound attachments/declarations, delete temporary credential imports and
remove private declaration files with the associated Inspection.
Always reverify before export; retain historical outputs and originals.
Test omissions, altered declarations, different PDF/version, wrong passwords,
unknown certificate trust, optional identity and long/mixed PDF fixtures.
Manual follow-up owned by the user: PDF layout/printing, Android sensors,
offline journey, storage/crashes and memory. No emulator, phone or native PDF
probe is run for this delivery; earlier probes cover only their earlier builds.
No unexecuted device or external trust check is marked as passed.
